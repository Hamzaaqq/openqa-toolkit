Laravel 12 and 13

The optional package provider automatically registers an Artisan command for auditing rendered Blade views.

composer require --dev hamzaaqq/openqa-toolkit:^0.1
php artisan openqa:view welcome --json

Use a view that renders without required data. If discovery is disabled, register OpenQA\Laravel\OpenQAServiceProvider::class in bootstrap/providers.php for your development environment. Only render trusted application code; this is not a sandbox. It does not exercise routes or browser behavior.

See the full Laravel documentation.

GitHub Actions

Check a generated or checked-in HTML file in a Linux workflow. Set up PHP first. The sample uses the published v0.1.0 tag; for production pin actions to reviewed commit SHAs.

name: HTML quality
on: [push, pull_request]
permissions:
  contents: read
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.3'
          extensions: dom, curl
          coverage: none
      - uses: Hamzaaqq/openqa-toolkit@v0.1.0
        id: audit
        with:
          file: public/index.html
          fail-on-findings: 'true'

Change the file path to match your project. Outputs are issue-count and report-path. Setting fail-on-findings to false keeps findings advisory; operational errors still fail. Avoid uploading confidential reports.
